## Визуальное решение

Сохраняем глубокие чернильно-сливовые поверхности, светлую лавандовую типографику и абрикосовый главный шаг. Поля пилота предлагают контекстные зарисовки тренера: фрагмент карты маршрута, следы и краткие наблюдения о походе, а не повторяющуюся веточку. Они не вводят механик и не намекают на неизвестных покемонов; функциональный текст остаётся читаемым нативным шрифтом. Вокруг наград, текста ошибки и внутри опасного подтверждения декор не размещать. Новые ограничения [ART-DIRECTION.md](../ART-DIRECTION.md) имеют приоритет над старым концептом и прежними растровыми листами.

Пять разделов слева, настройки снизу; валюта и встречи в общей шапке. Названия восьми маршрутов в один компактный ряд. Миниатюры из первого эскиза заменены короткими подписями, чтобы увеличить полезное место сцены. Полные названия доступны в заголовке выбранной сцены и accessibility name. Это предлагаемая компоновка пилота.

Новая предлагаемая роща — сухой близкий лес изнутри: стволы, корни и лесная подстилка рядом с наблюдателем, слои леса в глубине; без воды, пруда, озера и ручья. Прежний фон с водой и ботанические поля на старых листах не соответствуют этому уточнению и сохраняются только как история. Актуальные ссылки в этой спецификации ведут на файлы -v2.png; их визуальное принятие отдельно зафиксировано в ACCEPTANCE.md. Для всех восьми маршрутов действуют самостоятельные композиции из [ART-DIRECTION.md](../ART-DIRECTION.md), узнаваемые без подписи по силуэту, материалам и перспективе. Вулкан показывает близкие безжизненные базальт, реки лавы и жар; руины — тёмную замкнутую разрушенную архитектуру и тонкие анонимные глаза в тенях. Уют принадлежит UI, а сцены могут быть суровыми и таинственными по биому.

Сценовые заголовки допускают спокойную антикву; UI использует читаемый шрифт с кириллицей, начальная техническая опора — существующий BundledFont. Конкретное сочетание, веса и контраст фиксируются после настоящего WPF-пилота. Размер основного текста не уменьшать ради сохранения декоративного блока.

Порядок деградации при длинном контенте: убрать необязательный подзаголовок/уменьшить свободное поле → сократить высоту сцены → перенести группы управления/награды → прокрутка информационной области. Не сжимать шрифт/кнопки и не скрывать запуск за иллюстрацией. Окончательная минимальная высота проверяется R3.

Для подбора команды закрепляются заголовок/слоты и footer; прокручивается список страницы. В compact фильтры переходят в две/три строки, визуальная высота списка уменьшается; остаётся 12 записей на странице, не меняется игровая пагинация. Compact picker отдельно не нарисован: его поведение задано здесь, фактический layout подтверждает R3. Четыре state-панели — фрагменты содержимого, а не макеты целого окна каждого размера.

## Подготовка и данные примера

Демонстрационная команда: Bulbasaur, Chikorita, Pikachu, normal, три разных GUID; уровень10/XP1200, caring-parent, без второй особенности, нулевые дробные остатки. Активный Eevee остаётся вне команды.

Лесная роща, обычная сложность, 90 минут: **Равст ×3, 12 монет, 150 XP каждому**. Значения рассчитаны по коду, не получены новым прогоном приложения. Дополнительные находки/встреча в гарантированную строку не входят. В интерфейсе настоящие числа приходят только из preview/receipt сервиса, не из картинки или текста этого документа.

Карточки показывают имя/кличку, уровень, спрайт; при дублях — существующий discriminator, дата и accessible name. Не вводить постоянный номер экземпляра вместо GUID: нынешний ordinal может меняться с коллекцией. Декоративный порядковый маркер в сгенерированной Chikorita-карточке не означает новое правило — при отсутствии дублей не дублировать лишнюю метку.

Для1–2 участников поход доступен; показать «Добыча и опыт доступны. Для дополнительных находок и встречи нужны трое». Для3: «Полная команда: возможны находки и встреча». Пустая команда — нормальный начальный экран, не ошибка: нейтральная подсказка, основное действие «Выбрать команду», отправка недоступна. После выбора основное действие — отправка, изменение команды остаётся единственной небольшой ссылкой у заголовка.

При сомнении использовать нейтральное «Не удалось завершить действие. Проверьте состояние похода и повторите попытку».

## Подбор команды

Фильтры сохраняются: имя/кличка/номер, тип, открытая особенность, доступность, соответствие маршруту. Нет нового фильтра редкости. Сортировки: рекомендации / высокий уровень / номер. На рисунке «Доступные» отключён специально, чтобы показать недоступного Eevee; стандартное начальное значение остаётся включённым.

Рекомендации: доступные → подходящий тип → рекомендуемый уровень → уровень по убыванию → номер вида. В исправленном рисунке: два Bulbasaur, Butterfree, Chikorita, Pikachu, недоступный Eevee. Выбранные экземпляры не пересортировываются первыми искусственно, для них уже есть верхние слоты.

Страница содержит12 записей, рисунок показывает6 из них и внутренний scrollbar. При800 найденных —67 страниц. Числа являются сценарием stress-fixture; UI показывает фактические значения. Выбранность определяется checkbox и состоянием карточки согласованно; генераторная декоративная обводка не вводит ещё один тип выделения.

При выборе типа/особенности сохраняется реальное значение. Escape в picker отменяет черновик; возвращает фокус «Изменить/Выбрать команду». При пустом черновике поведение Готово сохраняет текущий контракт — не добавлять требование тройки. Причины недоступности: «На рабочем столе», «В походе», «В питомнике», «Изображение этой формы пока недоступно».

## Поход, получение и отмена

Время в рисунке (осталось45мин, возврат14:00) — пример отображения; ETA динамическая, активность может сокращать срок. Заполнение индикатора считать по actual state; не копировать долю из сгенерированного листа. Пользователь не видит формулы/проценты бонусов.

«Прервать поход» — небольшое вторичное действие. Подтверждение: «Прервать экспедицию?» / «Команда вернётся без добычи и опыта.»; безопасное «Оставить в пути», опасное «Прервать». Никаких частичных наград. После наступления ReadyAtUtc отмена невозможна, включая время, прошедшее с открытым диалогом.

Результат отделён от готовности: до claim «Находки ждут получения», после commit «Находки уже в запасах». Реальный receipt может включать доп.находки и разные XP участников; строку150каждому использовать только когда равенство действительно. Встреча — необязательный отдельный блок. На листе08 optional block показывает normal Bulbasaur как пример уже resolved известной встречи. Этот пример не обещает вид до claim; сам Catch flow остаётся R9/POKE-62 без нового RNG.

## Компоненты, фокус и движение

- Главный шаг абрикосовый, выбранные переключатели лавандовые; опасное подтверждение отдельной приглушённой красной роли.
- Disabled сохраняет читаемое объяснение. Empty не окрашивать в ошибку.
- Фокус видим на кнопке/вкладке/карточке/поле; выбор не обозначается только цветом.
- Modal удерживает взаимодействие, Escape отменяет; при закрытии фокус возвращается к инициатору, если тот существует.
- Во время pending блокируются изменяющие запрос контролы, включая маленькую ссылку изменения команды; навигация/закрытие следуют прежним lifecycle guards.
- Не добавлять бесконечные декоративные частицы/панорамирование. Статичная сцена + настоящие спрайты достаточно сохраняют жизнь. Windows reduced motion соблюдается.
- Скриншоты не доказывают контраст/фокус/DPI. Роли/размеры/текст проверяются на настоящих контролах R3.
