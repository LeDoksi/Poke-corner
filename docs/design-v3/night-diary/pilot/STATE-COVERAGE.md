Четыре реальные причины из `src/PokeCorner.App/Popup/ExpeditionTeamSelector.cs`, приоритет сверху вниз: **«На рабочем столе»**, **«В походе»**, **«В питомнике»**, **«Изображение этой формы пока недоступно»**. ## 08 — lifecycle details

Основа running/ready/result — лист04. Содержимое сохраняет route/team/terms, заменяются сообщение и footer. Ни один pending не объявляет успешную запись. Текст ошибки ниже — краткая предлагаемая строка; реальная причина остаётся доступна в подробностях. Закрытие/переход в другой раздел используют существующие lifecycle guards.

| ID | Visible/enabled / регион | Действие → переход |
|---|---|---|
| cancel-confirm | Текущий running затемнён; центральный confirmation, safe «Оставить в пути» с начальным фокусом, danger «Прервать». Body: «Команда вернётся без добычи и опыта.» | Safe/Escape → running; danger → перепроверка ID/status/clock, затем cancel-pending либо cancel-raced-ready |
| cancel-pending | Running сохранён за модалью; в action-row confirmation safe disabled и danger disabled «Прерываем…»; config/team read-only | Committed отмена → preparation без наград/XP; исключение → cancel-failure; никаких частичных наград |
| cancel-failure | Ошибка в confirmation; safe «Оставить в пути» enabled, явное красное «Повторить» enabled после await; running сохранён за модалью | Явное destructive Повторить снова перепроверяет snapshot/ID/clock перед отменой; safe отменяет намерение; если snapshot уже ready — ready, не Cancel |
| cancel-raced-ready | Confirmation закрыт; ready, полный progress, «Поход уже завершён. Заберите находки.» в message; Cancel hidden, claim enabled после await | Забрать находки → claim-pending; готовый поход не отменяется |
| claim-pending | Ready с прежними наградами/составом, CTA «Получаем находки…» disabled, Cancel hidden; участники ещё busy | Успешный commit → result; ошибка → reconciliation snapshot, обычно claim-failed |
| claim-failed | При snapshot ready сообщение «Не удалось получить находки. Повторите попытку.» и подробная причина; CTA «Повторить получение» enabled после await | Retry с прежним claim operation ID; если уже committed claimed — result, без повторной выдачи |
| result-with-encounter | Result receipt в содержимом; после наград отдельный optional block известного вида: normal Bulbasaur как пример уже определённой встречи, спрайт/имя и «Откройте встречу, чтобы добавить покемона». Кнопка «Открыть встречу»; «Продолжить» в footer | Открыть встречу → существующий Catch flow с этим encounter ID; ещё не добавляет экземпляр. Бросок/открытие и commit выдачи внутри Catch. Продолжить → preparation, unopened encounter остаётся в очереди |
| result-without-encounter | Тот же receipt, optional block полностью hidden, без «неудачи»/пустой ошибки. Продолжить enabled | Продолжить → preparation |
| legacy-result | Количества без receipt не показывать/не угадывать. В месте receipt: «Награды уже получены. Подробности этого похода не сохранились.» Optional encounter независимо от receipt | Продолжить либо Открыть встречу по фактическому encounter; новых наград за просмотр нет |

Вариант `result-with-encounter`: пример Bulbasaur — только для уже resolved существующей встречи, не обещание вида до claim и не новая прямая выдача развитой формы. Самостоятельная полная сцена Catch относится к R9; R2 задаёт optional block и переход. Открытая встреча (`opened`) не сохраняет активную кнопку «Открыть встречу»: показать «Встреча открыта.» и оставить Продолжить.

## Полная карта возврата `return-after-close`

Приоритет: актуальный опубликованный snapshot + известный исход операции; локальные cache/рисунок не доказывают запись. Перечитать состояние при открытии. Поздний callback не меняет скрытый view. Нельзя из одного отсутствующего результата в ещё не обновлённом snapshot заключать, что запись точно отказала.

| Snapshot / известная операция при возврате | Компоновка и разрешённые действия |
|---|---|
| Нет активного trip, нет неразрешённой операции | Preparation по валидному текущему selected; если draft закрытого picker потерян, не применять его автоматически |
| Start ещё in-flight и исход неизвестен | Preparation pending с заблокированным повторным стартом; дождаться существующего commit/reconciliation. Не генерировать новый operation ID и не писать «осталась дома» |
| Start отказал окончательно, trip не опубликован | Preparation error, сохранить доступный selected; retry прежнего request ID при сохранённом request; при изменении параметров новая операция |
| Start committed, snapshot running и clock < ReadyAtUtc | Running; локальный экран подготовки не имеет приоритета |
| Snapshot running, clock >= ReadyAtUtc или snapshot ready | Ready; отсутствие отдельной публикации ready не возвращает Cancel; claim разрешён по текущему producer contract |
| Cancel ещё in-flight / исход неизвестен | Соответствующий running/ready по snapshot + pending/reconciliation, не повторять mutation до завершения; clock может переводить в ready |
| Cancel committed и trip отсутствует | Preparation без выдачи наград; успешный результат только после подтверждения операции |
| Cancel отказал, trip running/ready | Running с ошибкой либо ready, действия по фактической готовности |
| Claim in-flight / исход неизвестен | Ready pending пока итог не установлен; при snapshot claimed перейти result. Не запускать claim новым ID |
| Claim окончательно отказал, snapshot ready/running уже по времени ready | Ready error, прежний ID для безопасного retry при его наличии |
| Snapshot claimed, receipt есть | Result по receipt, участники освобождены. Не claim повторно |
| Snapshot claimed, receipt отсутствует | Legacy-result, без придуманных количеств |
| Claimed + encounter resolved | Result-with-encounter; известный frozen вид, переход в Catch по ID |
| Claimed + encounter opened | Result с «Встреча открыта.», без повторного open; Продолжить |
| Claimed без encounter | Result-without-encounter |
| Пользователь ранее нажал Продолжить, локальный view жив | Preparation; committed receipt/очередь не стирать. После пересоздания view допустим показ сохранённого result по существующему контракту, не обещать persisted dismiss |
| Возврат из Catch/другого раздела | Новый snapshot решает claimed/result/очередь; не открывать другую встречу автоматически и не reroll |
| Процесс перезапущен, старые локальные IDs/результат операции не сохранены | Восстановить опубликованный persisted snapshot. Не обещать восстановление недолговечного draft или operation ID. Если producer требует recovery из-за неопределённой записи/профиля — безопасная ошибка/recovery, без нового расхода и без выдуманного успеха; private recovery остаётся POKE-34 |
| Snapshot недоступен/повреждён либо исход не удаётся установить | Ясная ошибка загрузки/восстановления; mutation disabled, безопасный выход/существующий recovery. Не подменять пустым новым профилем и не советовать бесконечный retry |
