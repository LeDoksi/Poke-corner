Статус: черновик системы, 28.10.2026, ждёт одобрения Georgy. Краткая выжимка и решения — в [DESIGN-BIBLE.md](../../project/DESIGN-BIBLE.md); здесь подробные размеры, состояния и правила компоновки для всего, что не сводится к цвету фона.

**Откуда значения.** Эталон — пилот экспедиций, принятый Georgy 22.10 (`Popup/ExpeditionView.xaml`, локальные стили в его `UserControl.Resources`). Где пилот и старые темы расходятся, прав пилот. | --- | --- | --- | --- |
| Покой | Абрикос | NdSurface + NdBorder | Обводка |

| Нажатие | NdApricotPressed | Фон NdRaised | Фон NdRaised |

| Ожидание записи | Недоступна, текст меняется на процесс («Отправляем…»), ширина не прыгает (MinWidth по самому длинному тексту) | То же | То же |

Недоступная главная кнопка без объяснения — ошибка. Причина пишется подписью 12 NdMuted прямо под кнопкой или слева от неё: «Добавьте хотя бы одного покемона», «Не хватает 3 ягод».

### Компоновка кнопок

1. **Где главная.** Внизу справа в колонке данных (экспедиции, питомник), на всю ширину только в узкой боковой странице. Её место не меняется между состояниями экрана: на подготовке, в походе и на возвращении главный шаг стоит в одной точке.
2. **Пара «выход / действие».** Выход слева, действие справа, зазор 12. Выход — вторичная кнопка с понятным словом: «Оставить» рядом с опасным (D-14), «Отмена» в подборе, «Назад» в пошаговом туре.
3. **Ряд действий карточки.** Повторяющиеся кнопки стоят в одной и той же позиции на каждой карточке (низ справа), даже если у части карточек действие недоступно, — тогда кнопка недоступна, а не исчезает. Иначе ряд «пляшет» при прокрутке.
4. **Не больше трёх кнопок в ряду.** Четвёртое действие уходит в тихую кнопку или в страницу питомца.
5. **Опасное — отдельно.** Опасная кнопка не стоит вплотную к главной: между ними минимум 24 или она в другом блоке.
6. **Esc и Enter.** Esc = кнопка выхода текущего слоя (оверлей → подбор → страница справа). Enter = главная кнопка оверлея, но не опасная: в подтверждении опасного действия Enter не срабатывает.

## 3. Выходы и навигация

Цель — ни одного тупика. Правила, по которым идёт аудит экранов:

| Слой | Как войти | Как выйти |
| --- | --- | --- |
| Раздел (Уголок, Покедекс, Экспедиции, Питомник, Магазин) | Рейка слева | Рейка всегда видна и активна, кроме открытого оверлея |
| Страница справа (питомец, вид) | Клик по плитке | ✕ в правом верхнем углу, Esc, клик по другой плитке меняет страницу |
| Подбор (команда, родители, питомец для предмета) | Кнопка «Выбрать…» или пустой слот | «Отмена» и Esc не меняют сохранённое; «Применить» — главная кнопка подбора |
| Оверлей подтверждения | Опасное или необратимое действие | Кнопка выхода слева и Esc. Клик по затемнению **не** закрывает (случайный клик) |
| Событие (вылупление, поимка, эволюция) | Результат действия | Одна главная кнопка следующего шага + тихая «В уголок». Анимацию можно пропустить кликом |
| Настройки | Шестерёнка внизу рейки, трей | Возврат в раздел, из которого пришли; рейка доступна |
| Тур | Первый запуск или «Повторить тур» | «Пропустить» на каждом шаге, «Назад» со второго |

**Переходы между разделами.** Если экран упоминает другой раздел, это тихая кнопка, которая ведёт туда с готовым контекстом (D-19: «Встретить: маршрут» открывает экспедиции с выбранным маршрутом). Текст-подсказка без перехода считается мёртвым.

**Нехватка ресурса.** Когда чего-то не хватает для главного шага, рядом с причиной стоит тихая кнопка к месту, где это взять («В магазин» с прокруткой к нужной ягоде).

## 4. Фильтры и поиск

Один набор на все списки: покедекс «Мои» и «Все виды», подбор команды, подбор родителей, выбор питомца для предмета. Элементы те же, что в принятом подборе команды (поле, выпадающие списки, флажки); новых контролов не вводим, только одинаковый порядок и подписи.

Первая строка: `[Поиск]  [Тип ▾]  [Редкость ▾]  [Особенность ▾]  ⟶  [Сортировка ▾]`
Вторая строка: `[☐ флажки-фильтры …]  ⟶  [Сбросить фильтры]`

| Элемент | Правило |
| --- | --- |
| Поиск | Поле 36 высотой, подсказка по тому, что реально ищется («Имя, кличка или номер»), ✕ очистки при непустом. Ищет сразу, без кнопки |
| Выпадающий фильтр | Подпись всегда «Что: значение»: «Тип: любой», «Редкость: любая». Сейчас в «Моих» стоит «Все типы» и «Редкость», в «Всех видах» — «Тип: любой»: приводим к одному |
| Сортировка | Всегда последняя справа, подпись «Сортировка: по номеру». Сейчас в покедексе она вторая, в подборе команды последняя |
| Флажок-фильтр | Вторая строка, зазор 16. Подписи по-русски: «Шайни», а не «Shiny» |
| Контекстный флажок | В подборе включён по умолчанию то, что следует из задачи: «Подходят маршруту», «Доступные», «Есть пара» |
| Счётчик | Подпись 12: «Показано 42 из 800», только когда что-то отфильтровано |
| Сброс | «Сбросить фильтры» справа во второй строке, видна только при активном фильтре или поиске |
| Режим (Мои / Все виды) | Сегмент над панелью фильтров, не внутри неё |

**Пустой результат.** Не пустая сетка, а блок по центру: «Никого не нашли» и кнопка «Сбросить фильтры». Пустая коллекция (а не пустой фильтр) — другое состояние со своим действием.

**На минимальном окне** со страницей справа поиск занимает свою строку, выпадающие делят следующую (так уже сделано в покедексе, `ArrangeFilters`). Горизонтальной прокрутки фильтров нет.

**Что фильтр помнит (предложение, решает Georgy).** Сейчас поведение разное по экранам. Предлагаю: фильтры раздела живут, пока открыто приложение; подбор каждый раз открывается с чистыми фильтрами, кроме контекстных.

Контролы, которые создаются в C# (`ShopView.AddRow`, подборы, карточки наград), берут те же ключи через `FindResource`, без своих цветов.

Порядок: (1) канон в NightDiary.xaml и алиасы — визуально почти ничего не меняет на экранах, проверяется скриншотами всех разделов; (2) неявный Button → вторичный, пройтись по экранам и явно пометить единственную главную; (3) чистка локальных копий. Каждый шаг — отдельный коммит и скриншоты 1200×660 и FullHD.
