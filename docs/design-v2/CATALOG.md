# Каталог и редкости

Распределение редкостей v2 принято пользователем как рабочая основа. Для активности одобрены базовые веса 60/30/9/1, затем явно запрошены 80% нового вида и гарант нового покебола после дубля. Это заменяет удвоенные веса неизвестных видов. Пулы и ограничение текущей доступностью — ENCOUNTERS.md; влияние гарантии на редкости и темп ещё проверить.

## Второй проект распределения — для обсуждения

По просьбе пользователя улучшить баланс подготовлен rarity-draft-v2.json. Эволюция сохраняет редкость. Первое распределение сохранено в rarity-draft.json для сравнения; новый вариант не применяется в runtime.

Правила v2: флаги legendary/mythical → Legendary; семьи стартеров, Eevee и перечисленных восстановленных из ископаемых видов → Uncommon как явные игровые исключения. Для остальных capture_rate начального вида >=150 → Common, >=60 → Uncommon, иначе Rare. Списки исключений явно заданы по ID корня семьи в build-rarity-draft.mjs, не зависят от имени или случайного порядка каталога.

Полный каталог: Common 545, Uncommon 243, Rare 143, Legendary 94. Текущие BW-виды: 470/199/118/81 (868). Без BW: 75/44/25/13 (157). Семьи: 242/113/98/88. Проверены все эволюционные переходы и официальные флаги; стартовая и финальная стадии имеют одинаковую редкость. Пороги и игровые исключения пока предложены, не утверждены.

Количество видов не задаёт вероятность выпадения: будущий генератор должен сначала выбрать редкость по игровым весам, затем подходящий вид внутри пула, а не равномерно выбирать среди всех 868. Точные веса ещё не утверждены. Число канонических легендарных+мифических в полном каталоге остаётся 94; сокращать его ради формы распределения не предлагалось.

## Редкость при эволюции и первый проект распределения

Пользователь явно уточнил: эволюция редкость НЕ повышает. В проекте фиксируется одна редкость всей эволюционной семье; переход между видами её сохраняет. Это заменяет прежнее предложение назначать независимые редкости стадиям и допускать повышение.

Создан rarity-draft.json для всех 1025 видов, 541 семьи, на основе закреплённых данных пакета. Члены одной семьи определены через evolves_from_species_id с проверкой отсутствия циклов и потерянных родителей. Все переходы проверены на одинаковую редкость.

Первый автоматический проход: канонический legendary/mythical флаг → Legendary; иначе capture_rate начального вида семьи >=150 → Common, >=70 → Uncommon, меньше → Rare. Низкий capture_rate обычного вида сам по себе больше не делает его Legendary. Выбранные пороги используют текущую классификацию как ориентир, а не окончательный баланс.

Итого: Common 545 видов/242 семьи, Uncommon 113/60, Rare 273/151, Legendary 94/88. Из них с обычной BW-анимацией: 470/90/227/81 (в сумме 868); без BW: 75/23/46/13 (157). Таблица содержит источники голоса и отдельные признаки обычной/shiny анимации, но не подменяет нерешённые проверки шести identical-shiny пар.

Проверены границы порогов, Mew как Mythical→Legendary, одинаковая редкость Bulbasaur/Venusaur и Eevee/Leafeon, отсутствие смешанных legendary-флагов в семье. Файл подготовлен build-rarity-draft.mjs; runtime и сохранения не изменялись.

Открытый вопрос: стартеры и семья Eevee автоматически попали в Rare из-за capture_rate=45. Возможное игровое исключение — Uncommon для этих семей; пока НЕ применено. Фиксированный набор общих редкостей не является итоговой вероятностью выпадения: веса, маршруты и рецепты балансируются отдельно.

Звук остатка согласован: 717 видов — itch, 127 — Pixelmon, 24 временно с cries.latest PokéAPI. Отсутствие аниме-голоса у этих 24 не блокирует игровую доступность. Задача замены — POKE-31 [hold]; выбранные источники в voice-preview/selected-sources.json. Временные крики пока не скачаны/не интегрированы, это зафиксированная политика, а не готовый runtime.

## Единый BW и полный пакет данных — решение и подготовка

Пользователь выбрал только Black & White, без автоматического смешивания с Showdown. Полный каталог данных всех видов используется для баланса, рецептов и информации. Игровые источники не должны выдавать виды/варианты, для которых ещё нет подходящей анимации; запрет охватывает активность, экспедиции, питомник и эволюцию. Существующую коллекцию при миграции не удалять.

В покедексе различать доступный непойманный вид (силуэт) и пока неподдерживаемый вид (без силуэта, нейтральная заглушка и «Этот вид ещё никто не встречал»). Для второго можно показывать сведения вида — имя/номер, тип, краткое описание — без внешности; точную подачу ещё обсудить. Недоступные результаты/рецепты явно помечать «Пока недоступно». Не списывать ресурсы за недоступный выбранный результат. Полная будущая сеть рецептов хранится отдельно от текущего разрешённого пула; правила перерасчёта вероятностей неполных рецептов ещё согласовать. Цели достижений не должны становиться недостижимыми из-за отсутствующих ресурсов; конкретные условия версии ещё согласовать.

## Согласованная шкала

Покеболы за активность могут дать любой вид поддерживаемого каталога из всех четырёх редкостей, включая легендарных и мифических с очень небольшим шансом. Точные вероятности ещё не заданы. Содержимое скрыто до открытия; решение не подтверждает готовность ассетов полного каталога. Экспедиции ограничивают возможные встречи местностью, питомник даёт целевые рецепты.

Четыре игровые редкости: обычный → необычный → редкий → легендарный. Мифические объединяются с легендарными в последней игровой категории. Пятая ступень не вводится. Shiny — отдельный признак, не ступень редкости.

Для общей категории действуют правила легендарных рецептов питомника: один рецепт разных родителей на вид и не больше одного легендарного результата у пары. Достижение «Легенды рядом» должно включать и мифических. Каноническую принадлежность к мифическим можно сохранять в данных/описании отдельно от игровой редкости.

## Текущая реализация и требуемая корректировка

В src/PokeCorner.Core/Domain/RarityClassifier.cs редкость сейчас определяется только captureRate: >=150 Common, >=70 Uncommon, >=30 Rare, иначе Legendary. Это не подтверждает каноническую принадлежность вида к легендарным/мифическим. При подготовке полного каталога верхнюю категорию определять по принадлежности к этим группам; остальные три балансировать отдельно, используя captureRate как ориентир.

Полный перечень видов, форм, канонические флаги, распределение остальных редкостей, покрытие анимациями/голосами и сеть рецептов ещё не проверены. Код классификации и сохранения на этапе дизайна не менялись. При реализации учесть миграцию нынешней редкости без потери коллекции и наград.
