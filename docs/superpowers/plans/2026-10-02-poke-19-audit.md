# POKE-19: аудит и чистка ядра — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Закрыть POKE-19 (полный аудит), а с ним POKE-21, POKE-22 и POKE-24. Удалить мёртвый код и дубли, вырезать из комментариев историю правок, убрать работу с диском из потока хуков ввода, оставить одну копию приложения, добавить пояснения в интерфейс. Выпустить MSI 1.0.17.

**Architecture:** Удаления и дедупликация не меняют поведения, их проверяет зелёный набор тестов. Каждое изменение поведения начинается с падающего теста. Новая логика, которую можно тестировать, выносится в Core.

**Tech Stack:** .NET 8, WPF, xUnit, WiX 5.

**Spec:** нет отдельного документа. Требования — аудит от 2026-10-02 (в чате) и ответы пользователя:
- историю правок из комментариев вырезать;
- в объём входят A (автосохранение), B (POKE-22), C (геймпад), D (POKE-21), а также POKE-24 (пояснения на талисмане, странице поимки и купленном яйце);
- проверка функций — чеклист, по которому пользователь сам проходит приложение.

## Global Constraints

- `dotnet build PokeCorner.sln` → 0 предупреждений; `dotnet test PokeCorner.sln` → всё зелёное.
- Формат `state.json` не меняется: старые сейвы читаются как есть.
- Тексты интерфейса — на русском, в стиле существующих.
- Комментарий остаётся, только если объясняет, **почему** код такой (ограничение платформы, неочевидный инвариант, измеренная причина). Пересказы «раньше было / Task N / исправлено, потому что» удаляются.
- Новых зависимостей нет.

## Review Focus

1. Выход из приложения сразу после автосохранения из пула потоков: на диске остаётся последний снимок, а не более старый. Тест — Task 3.
2. «Сбросить сейв и перезапустить» при защите от второго экземпляра: новый процесс дожидается выхода старого и не завершается сам. Тест — Task 4.
3. Alt+F4 на питомце в фокусе: процесс не остаётся работать без питомца. Тест — Task 4.
4. Повторная покупка талисмана, пока он активен: монеты не списываются. Тест — Task 7.
5. Удаление «мёртвого» кода не задевает привязки XAML (`{Binding X}`): перед удалением члена проверить XAML через grep. Проверка — Task 1.
