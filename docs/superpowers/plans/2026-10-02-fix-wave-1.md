# Фикс-волна 1 (бэклог POKE до глобальных апдейтов) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Закрыть бэклог проекта `pokecorner` на доске (POKE-1…6, 8, 9, 16, 18, 20) одной волной и выпустить MSI 1.0.14.

**Architecture:** Сначала fast-forward master на готовую ветку, дальше работа на ветке `fix-wave-1`. Доменные правки (CatchRoller, ShopService, SpeciesCatalog, EvolutionThresholds) делаются в Core и закрываются тестами. Правки WPF-оболочки (декодирование спрайтов, z-order) проверяются замером и живым смоук-тестом.

**Tech Stack:** .NET 8, WPF, xUnit, WiX 5.

**Spec:** нет отдельного документа. Требования взяты из карточек POKE-* на доске и из решений пользователя от 2026-10-02:
- POKE-16: талисман тратится на первое событие, поимку или вылупление.
- POKE-20: порог 280 000 → 196 000.
- POKE-9: питомец уходит **под другие окна**, всегда на втором мониторе, паттерна нет.
- POKE-19 (полный аудит) идёт отдельной волной **после** этой.

## Global Constraints

- Тексты интерфейса на русском, в стиле существующих (см. `ShopView.xaml`).
- Новых NuGet-зависимостей не добавлять.

- Формат сохранения (`SaveData`) не меняется.

### Task 2: Подбор натуры для дубля по своей цепочке (POKE-2)

**Files:**

**Interfaces:**
- Produces:
  - `CatchResult RollCatch(IReadOnlyList<SpeciesEvolutionChain> allChains, IReadOnlyCollection<PokemonIndividual> owned, double shinyChanceMultiplier = 1.0)`
  - `CatchResult RollCatchFromTier(IReadOnlyList<SpeciesEvolutionChain> allChains, RarityTier tier, IReadOnlyCollection<PokemonIndividual> owned, double shinyChanceMultiplier = 1.0)`

Причина бага: цепочку выбирает сам `RollCatch`, поэтому вызывающий код не может заранее передать натуры именно этой цепочки. Сейчас оба вызова передают натуры **всех** пойманных покемонов. Чиним в одном месте: `RollCatch` получает список пойманных особей, сам строит `ownedChainIds` и после выбора цепочки берёт натуры только её особей.

- [ ] **Step 1: Падающий тест** `RollCatch_DuplicateNatureBias_UsesOnlyThePickedChainsNatures`. Seed `new Random(42)`, `allChains` = одна цепочка A. Пойманы: одна особь цепочки A с натурой `Nature.Hardy`, плюс по одной особи цепочки B на каждую из остальных натур (`Enum.GetValues<Nature>().Except([Hardy])`). Делаем 2000 бросков. Проверка: доля `Hardy` < 0.05. При правильной логике ожидается ≈ 0.3/24.3 ≈ 1.2%, при старой ≈ 1/8.2 ≈ 12%.
- [ ] **Step 2: Запустить тест, он падает.** `dotnet test tests/PokeCorner.Core.Tests --filter RollCatch_DuplicateNatureBias_UsesOnlyThePickedChainsNatures`. Ожидается FAIL (тест не компилируется или доля ≈ 0.12).
- [ ] **Step 3: Реализация.** Новые сигнатуры из Interfaces. Внутри: `ownedChainIds = owned.Select(i => i.EvolutionChainId).ToHashSet()`, после `PickChain` — `owned.Where(i => i.EvolutionChainId == chain.ChainId).Select(i => i.Nature).ToHashSet()`. Существующие 7 вызовов в `CatchRollerTests` перевести на список `PokemonIndividual`, утверждения не менять. В `App.xaml.cs` оба места передают `_appState.Collection.Individuals`, локальные `ownedChainIds`/`ownedNatures` удалить.
- [ ] **Step 4: Тесты проходят.** `dotnet test tests/PokeCorner.Core.Tests` → PASS.
- [ ] **Step 5: Коммит.** `git commit -am "Bias duplicate natures against the picked chain only, not the whole collection (POKE-2)"`

Гипотеза (подтвердить по логу `zwatch.log` наблюдателя из сессии 2026-10-02 перед правкой):

`SetWindowPos(hwnd, Shell_TrayWnd, …)` делает окно topmost не всегда. Окно становится topmost, только если **под** панелью задач в topmost-слое уже есть другие topmost-окна. На 02.10 под ней лежат окно `WDADesktopService` и `Shell_SecondaryTrayWnd`. Если панель оказывается последним topmost-окном, питомец встаёт в начало обычного слоя без флага `WS_EX_TOPMOST`. Дальше переподъём раз в секунду через `HWND_TOP` не работает: это задокументировано в самом комментарии метода — Windows не даёт процессу без фокуса поднять окно выше окна переднего плана. Отсюда «нет паттерна»: всё зависит от того, какие topmost-окна существуют в данный момент.

Внешний наблюдатель за 15 минут 02.10 не поймал падения флага, и симптом за это время не проявился. Поэтому по решению пользователя диагностика встраивается в само приложение и уезжает в 1.0.14 к девушке и другу.
