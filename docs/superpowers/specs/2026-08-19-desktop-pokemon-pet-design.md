# Desktop Pokémon Pet (Windows) — дизайн-документ

**Дата:** 2026-08-19
**Статус:** утверждено, готово к написанию implementation-плана
**Рабочее название проекта:** PokéCorner (плейсхолдер, легко переименовать)

## Идея

Вдохновлено [PokeTokenBar](https://github.com/chattymin/PokeTokenBar) (macOS-only, Swift/SwiftUI), но
не порт, а самостоятельное Windows-приложение с другой основной механикой роста. Питомец-покемон живёт
в углу экрана, как тамагочи: растёт от активности пользователя за компьютером (а не только от токенов
AI-инструментов), его можно кормить/гладить, он эволюционирует по реальным эволюционным линиям, время от
времени можно поймать нового случайного покемона, между пойманными можно переключаться.

Ключевое отличие от прототипа: трекинг токенов — **опциональная фича, выключаемая в настройках**, а не
центральный механизм.

## Стек и архитектура

Единое WPF-приложение (.NET 8), один процесс:

- **Трей-иконка** (`NotifyIcon`/`Hardcodet.NotifyIcon.Wpf`) — быстрый доступ к попапу и настройкам,
  видимый индикатор, когда включён трекинг активности.
- **Плавающее окно питомца** — отдельное borderless, always-on-top, layered-window (per-pixel
  transparency) в углу экрана. Click-through везде, кроме hit-box самого спрайта. Перетаскивается,
  положение и монитор запоминаются.
- **Рендер спрайта** — нативно через WPF `Image` + `DispatcherTimer` для покадровой смены пиксель-арт
  спрайтов (кадры Gen-V стиля, как в оригинале). Плавные переходы, покачивание, драг, попапы — через
  встроенные WPF `Storyboard`/`DoubleAnimation` (GPU-композитинг), без браузерного движка.
  - Решение зафиксировано после сравнения с вариантом на WebView2: исходный материал (пиксель-арт
    спрайты) не выигрывает от векторного/CSS-рендера, а WebView2 добавляет ~80-150МБ RAM на процесс,
    более медленный холодный старт и известные баги с настоящей прозрачностью поверх layered window —
    несоразмерная цена для фонового приложения, которое должно тихо висеть 24/7.
- **Данные** — локально, JSON (переход на SQLite, если коллекция вырастет) под `%AppData%\PokeCorner`.
  Спрайты PokeAPI скачиваются один раз и кешируются локально — дальше приложение работает офлайн.
  Никакой отправки данных наружу, кроме самой загрузки спрайтов с PokeAPI.

## Основной игровой цикл

- Единая валюта прогресса — **Care Points**. Копится пассивно от глобальной активности мыши/клавиатуры.
- **Активность считается через low-level Windows hooks** (`SetWindowsHookEx`, `WH_MOUSE_LL` /
  `WH_KEYBOARD_LL`) на отдельном потоке. **Важно:** хранится и инкрементируется только счётчик событий —
  ни код клавиши, ни содержимое ввода, ни заголовки окон никогда не сохраняются и не логируются. Это
  принципиально и для приватности, и чтобы антивирус не принял приложение за кейлоггер. Трекинг —
  единственный toggle-переключатель с явным индикатором в трее, когда активен (kill switch).
- Эволюция — по настоящим эволюционным линиям через PokeAPI (Gen 1-5, как в оригинале), пороги по Care
  Points, стартовый вид при поимке/хатче выбирается взвешенно по редкости (как в прототипе).
- Первый запуск — онбординг с яйцом: копим Care Points до хатча, вылупляется случайный стартовый вид.
  Если на первом запуске нет интернета — используется небольшой офлайн-набор спрайтов для базовых
  стартовых линий, чтобы приложение полностью работало без сети с первого раза; остальные виды
  подгружаются с PokeAPI по мере необходимости.

### Кормление / поглаживание

Настройка **Feeding mode**:
- **Simple** — мгновенный клик по кнопке в попапе или по самому питомцу, без ограничений.
- **Economy** — лакомства/игрушки зарабатываются активностью (мини-инвентарь), тратятся при кормлении.

### Опциональный трекинг токенов CLI-инструментов

Выключено по умолчанию, включается в настройках. При включении токены **добавляются в тот же пул Care
Points**, что и клики/нажатия — единая механика роста, токены просто ещё один источник.

Механизм подтверждён на реальных данных этой машины: Claude Code пишет локальные логи сессий в
`%USERPROFILE%\.claude\projects\<закодированный-путь-проекта>\<session-uuid>.jsonl` — тот же формат,
что и на macOS, только путь резолвится через `%USERPROFILE%`. В строках ответов ассистента есть поле
`usage` вида:

```json
"usage":{"input_tokens":2,"cache_creation_input_tokens":562,"cache_read_input_tokens":133657,"output_tokens":635,...}
```

Провайдер читает `.jsonl`-файлы, суммирует `input+output+cache` токены за сегодня — без вызова CLI,
без сети. Реализуется как отдельный `IUsageProvider` (Claude Code, позже опционально Codex и др.) за тем
же интерфейсом, что и счётчик кликов — оба просто поставляют очки в общий пул.

## Поимка новых покемонов и коллекция

- Шанс поймать нового покемона роллится **каждые N событий накопленной активности** (клики + нажатия,
  и опционально токены, если включены). **Без ограничения "не чаще раза в 24 часа"** — чисто по
  активности, сколько наиграл, столько и шансов.
- Новый покемон уходит в **коллекцию**. В попапе можно в любой момент выбрать, кто из пойманных сейчас
  "живёт" на рабочем столе — остальные просто хранятся, не теряются.

## Уход за питомцем (Care mode)

Настройка с двумя режимами:

- **Chill** (по умолчанию) — голод/настроение медленно падают со временем без ухода, питомец выглядит
  грустным, но **ничего не пропадает навсегда** и с рабочего стола не исчезает.
- **Hardcore** — при долгом игноре активный питомец **уходит с рабочего стола сам** (десктоп остаётся
  пустым, никто не подставляется автоматически). Показывается попап: "<Имя> расстроен и не хочет
  возвращаться на стол ещё 1 час". Через это время именно этот покемон снова доступен для размещения;
  **при этом в любой момент можно вручную поставить на стол другого** пойманного покемона из коллекции —
  ограничение действует только на конкретного обиженного. Из коллекции покемон никогда не удаляется.

## Не мешать пользователю

Питомец не должен перекрывать полноэкранные окна (игры, видео, презентации):

- Детект полноэкранного режима через win32: `GetForegroundWindow` + `GetWindowRect` сравниваются с
  границами монитора и стилем окна (тот же приём, которым сама Windows скрывает taskbar в играх/видео),
  с исключением системных/shell-окон.
- При фокусе на полноэкранном приложении питомец автоматически скрывается/затухает; при потере фокуса —
  возвращается.
- Вне fullscreen-режима питомец всегда click-through за пределами своего спрайта, так что не блокирует
  клики мимо себя даже в оконном режиме.

## Настройки

- Care mode: Chill / Hardcore
- Feeding mode: Simple / Economy
- Трекинг токенов: вкл/выкл (выкл по умолчанию), выбор источников (Claude Code, позже другие)
- Трекинг активности (мышь/клавиатура): вкл/выкл — мастер-переключатель с индикатором в трее
- Авто-скрытие в fullscreen: вкл/выкл
- Позиция/угол экрана и монитор, размер спрайта
- Автозапуск при входе в Windows
- Сброс данных / удаление коллекции (для переустановки "с нуля")

## Данные и edge cases

- Мультимонитор — запоминается конкретный монитор и угол; если монитор отключён при следующем запуске,
  падать обратно на primary.
- Приложение было закрыто несколько дней — никакого "докатчапа" не нужно, т.к. прогресс завязан на
  активность, а не на прошедшее время (в отличие от прототипа с daily/weekly лимитами).
- PokeAPI недоступен при первом запуске — офлайн-фоллбэк набор стартовых спрайтов (см. выше), остальное
  подгружается лениво с ретраями, когда появится сеть.
- Данные — только локально, без аккаунтов и облачной синхронизации.

## Вне скоупа (сознательно не делаем сейчас)

- Синхронизация коллекции между несколькими ПК/облако.
- Официальные daily/weekly usage-лимиты и предупреждения (это было специфично для оригинала как трекера
  токенов — здесь трекинг токенов вторичен).
- Множественные одновременные питомцы на столе (сейчас — один активный, остальные в коллекции).
- Магазин/платная экономика (Economy-режим кормления — просто локальный инвентарь, не покупки).

## Тестирование

- Модульные тесты на чистую логику без UI: расчёт Care Points, пороги эволюции, вероятность
  поимки/редкости, переходы Care mode (Chill/Hardcore), Feeding mode (Simple/Economy) — эти компоненты
  изолированы от WPF и хуков, тестируются независимо.
- UI/hook-поведение (overlay-окно, click-through, low-level hooks, fullscreen-детект) тестируется вручную
  на реальной машине — не поддаётся дешёвой автоматизации, но покрывается смоук-сценарием при каждом
  значимом изменении (питомец растёт от активности, ловится новый, эволюционирует, корректно
  скрывается в fullscreen-игре/видео).
