Отдельная вкладка · конкретные замечания

Проблемы данных и как их закрыть

Диагноз по текущей реализации + источники решения
Да — текущий охват намеренно ограничен

Приложение обходит только 1–649

Проверил live endpoint: /pokemon-species/ возвращает count: 1025. Запись /pokemon-species/1025/ тоже существует — это Pecharunt, поколение IX. В проекте же SpeciesCatalog.RefreshFromNetworkAsync по умолчанию обходит только ID 1–649, а fallback и seed-пакет собраны для Gen I–V. Значит, проект охватывает первые 649 из 1025 видов API; ещё 376 видов сейчас отсечены границей проекта, не отсутствуют в PokéAPI.

Как расширить правильно

  1. Брать список через /pokemon-species?limit=…&offset=…, а не оставлять магическую константу 649.
  2. Собирать виды и цепи с дедупликацией по ID цепочки; для новых видов загружать имена, типы и спрайты.
  3. Добавить регион/поколение в модель каталога, чтобы можно было включать новые регионы постепенно.
  4. Решить, когда новый вид становится доступен в catch/egg-пулах; обновить редкость и экономику.
  5. Пересобрать стартовый офлайн-пакет и проверить размеры MSI/первый запуск без сети.

Варианты охвата

  • Лёгкий: все species доступны как данные Покедекса, но поимка остаётся Gen I–V.
  • Региональный: выбрать Gen VI–IX и включить по одному региону за раз.
  • Полный: все species/формы из API в Покедексе, а доступность видов в игре контролируется отдельным флагом/кампанией.

Совет: не смешивать «API знает» и «игра выдаёт». Так новые формы можно исследовать до того, как они попадут в баланс поимки.

Проверяемые источники: листинг API (count: 1025) · вид №1025 — Pecharunt · документация PokéAPI · локальный код: src/PokeCorner.Core/PokeApi/SpeciesCatalog.cs, SpriteCache.cs.

Похоже, старые не только на слух

Крик сейчас берётся из заранее вложенного WAV

Приложение проигрывает Data\cries\{speciesId}.wav. Загрузка выполняется заранее, а при клике приложение только читает локальный файл — свежей проверки или скачивания в runtime нет. В коде не хранится метка latest/legacy, поэтому точный вариант источника старого файла нельзя надёжно подтвердить по самому runtime-коду; обновить и зафиксировать происхождение нужно на этапе seed-сборки.

Самый простой путь

  1. В seed-генераторе брать pokemon/{id}.cries.latest, а если отсутствует — legacy.
  2. Конвертировать OGG в совместимый WAV, как уже делает проект, и записывать выбранный вариант в manifest.
  3. Пересобрать офлайн-пакет; при желании сначала проверить несколько разных поколений на слух.
  4. Отсутствующий cry оставлять нормальным состоянием, а не ошибкой запуска.

Откуда взять

  • PokeAPI/cries — официальный репозиторий файлов latest и legacy в OGG; в README заявлены поколения I–IX.
  • Папка latest/ для более современных записей; legacy/ — исторические cry до №649.
  • Данные в репозитории загружены из Pokémon Showdown и Veekun, поэтому «latest» означает актуальный доступный набор, а не оригинальную запись из каждой последней игры.

Для проекта лучший компромисс: latest при сборке + конвертация в WAV + локальный кэш. Не скачивать звук при каждом поглаживании: приложение остаётся офлайн-дружелюбным и не зависит от сети. Источник проекта: installer/README.md, src/PokeCorner.App/App.xaml.cs, src/PokeCorner.App/AppPaths.cs.

Да — API отдаёт дерево, но приложение его сплющивает

Альтернативная ветка теряется при импорте

PokéAPI присылает рекурсивное дерево evolves_to с несколькими детьми и условиями перехода. Однако CollectStages в PokeApiClient.cs выбирает только самый длинный дочерний путь. Модель SpeciesEvolutionChain хранит линейные списки StageSpeciesIds/StageTypes. Поэтому UI и логика стадий не могут показать/выбрать оставшиеся ветви, хотя источник уже их содержит.

Вариант 1 · только показать дерево

Сохранить каждую ветку и условия как дерево, отобразить его в профиле. Текущий уход и эволюция остаются без изменений.

Малый риск, хорошая справочная ценность; в коллекции всё ещё нужен выбранный вид.

Вариант 2 · разблокировать выбором

Care Points открывают эволюцию как сейчас, но на развилке игрок выбирает целевую ветку. Предмет, характер или биом могут быть дополнительными опциональными условиями.

Сохраняет философию «растёт от заботы» и использует реальные варианты видов, не притворяясь точной боевой RPG.

Что хранить

Вместо массива стадий — дерево узлов «species ID + дети», а на рёбрах — поля условий из evolution details (предмет, уровень счастья, время суток, локация, известная атака и версия). Для уже сохранённых Pokémon можно мигрировать существующий stage-путь в выбранную ветку; ничего из старых сохранений не должно случайно менять вид.

Источники: пример цепи PokéAPI · документация эволюции · локально: src/PokeCorner.Core/PokeApi/PokeApiClient.cs, src/PokeCorner.Core/Domain/SpeciesEvolutionChain.cs.

Да — сейчас загрузчик запрашивает только обычный спрайт

Shiny-флаг в сохранении не выбирает shiny-файл

PokemonIndividual.IsShiny уже сохраняется, но FetchSpriteAsync(speciesId) строит один URL вида …/pokemon/{id}.png. У этого метода нет аргумента shiny/form, а SpriteCache использует ключ только {speciesId}.png. Поэтому возможность получить shiny есть в API, но текущий путь загрузки/кэша её не выбирает. Для отдельных Pokémon и форм отличия shiny могут быть очень тонкими — полезно проверять оба варианта рядом.

Базовое исправление

  1. Получать JSON /pokemon/{id} и брать URL sprites.front_default или sprites.front_shiny по сохранённому флагу.
  2. Добавить отдельные ключи кэша для normal/shiny; не позволять обычному PNG перезаписывать shiny.
  3. Если shiny sprite для вида отсутствует — явно fallback на обычный спрайт и показать/сохранить статус без аварии.
  4. Проверить, что оверлей, карточка коллекции и экран поимки используют один resolver изображения.

Другие источники изображений

  • PokeAPI/sprites и поля URL самого PokéAPI — самый прямой путь для статических normal/shiny и части форм.
  • Pokémon Showdown animated sprites — вариант для пиксельной анимации; для shiny есть отдельные наборы.
  • Данные Showdown — актуальная структурированная информация о видах, формах, поколениях и эволюционных правилах.

У форм нужен ключ изображения из нескольких частей: вид/форма + shiny (и при необходимости пол). Автоматическое раскрашивание обычного спрайта не заменяет настоящий shiny sprite: палитры отличаются по-разному. Массовые игровые изображения — чужие IP; перед распространением новых asset-паков проверить условия использования/распространения. Текущие локальные точки: src/PokeCorner.Core/PokeApi/PokeApiClient.cs, SpriteCache.cs, вызовы обновления оверлея.

Варианты для игры

Карточка / Покедекс

Профиль питомца с историей вида

Хорошо ложится

В карточке коллекции показывать категорию, цвет, среду обитания, записи Покедекса, номер в региональном списке и варианты вида. Дать переключать текст записи между играми или языками, если нужная локализация присутствует.

pokemon-speciespokemon-colorpokemon-habitatpokedex

Почему подходит: использует уже существующий вид и коллекцию; не меняет баланс и может работать офлайн из кэша. Данные описаний по версиям нужно выбирать аккуратно.

Кормление / персональность

Ягоды и вкусовые предпочтения

Лучший кандидат

Разделить лакомства на ягоды с вкусами и эффектами. Связать вкус с Nature: любимая ягода даёт немного больше Care Points или особую реакцию; нелюбимая остаётся съедобной, но без бонуса. Можно выращивать ягоды за активность и ждать созревания.

berryberry-flavornatureitem

Особенно удачно: проект уже хранит Nature, лакомства, остаток активности и магазин. Нужны собственные правила цен/бонусов; API описывает игровые параметры ягод, а не баланс десктопного питомца.

Визуальная коллекция

Формы, пол и Shiny-спрайты

Хорошо ложится

Показывать альтернативные формы одного вида, отличия самца/самки там, где они есть, и настоящий shiny-спрайт. Добавить формы как вариации записи Покедекса либо как отдельные коллекционные экземпляры.

pokemonpokemon-formpokemon-species.varieties

У Shiny уже есть игровой флаг, поэтому вариант спрайта — естественное визуальное улучшение. Разные формы глубже затронут идентификаторы коллекции и правила дублей.

Реакции питомца

Больше звука и характера

Быстрый эффект

Показывать название/описание способности и иногда учитывать её в реакции на клик, заботу или находку. В качестве альтернативы — брать latest/legacy cry по виду или дать выбрать крик, если в проекте уже есть подходящие локальные файлы.

abilitypokemon.abilitiespokemon.cries

Крики в приложении уже предусмотрены, значит API-вариант может дополнить текущий набор. Для пассивных эффектов нужны безопасные, понятные правила — игровые способности часто рассчитаны на сражения.

Активность / Поимка

Экспедиции по биомам

Нужна механика

Игрок выбирает «лес», «пещеру» или «побережье»; активность за компьютером продвигает вылазку и открывает тематические встречи. Можно сделать ежедневные маршруты или короткие события вместо постоянной новой карты.

location-areapokemon.encounterspokemon-habitatregion

Данные встреч привязаны к версии игры, методам и условиям. Их придётся нормализовать и превратить в стабильные игровые пулы, сохранив существующий каталог Gen I–V или отдельно согласовав расширение.

Покедекс / Долгие цели

Региональные коллекции и задания

Нужна механика

Добавить страницы региональных Покедексов, процент завершения, награды за набор типов/цветов/сред обитания и «покемона дня». Уже имеющаяся коллекция становится не просто списком, а прогрессом в исследовании.

pokedexgenerationregionpokemon-species

Дешёвый первый шаг — только прогресс и значки. Награды с валютой и вероятность встреч повлияют на экономику и повторные поимки.

Эволюция / Справка

Ветка и оригинальные условия эволюции

Справка — да

Показать семейное дерево и как вид эволюционирует в оригинальных играх: уровень, счастье, предмет, время дня, локация, атака или погода. Можно подсвечивать будущие стадии, не меняя текущую эволюцию за Care Points.

evolution-chainevolution-triggeritemversion-group

Хорошая справка для коллекции. Полное перенесение условий конфликтует с нынешней простой системой заботы и требует обработки многих исключений и ветвлений.

Мини-игра / Стиль

Конкурсы и «витрина» питомца

Нужна механика

Небоевая цель: раз в день выбрать стиль — Cool, Cute, Beautiful, Smart или Tough — подготовить ягоду/украшение и получить оценку. Можно применять выбранные атаки как темы для карточки или анимации.

contest-typecontest-effectmove.contest-typeberry-flavor

Данные легко превращаются в коллекционную мини-активность, но рейтинги и призы придётся проектировать самим. Полная оригинальная система конкурсов будет слишком большой для питомца в трее.

Боевой справочник

Атаки, статы и таблица типов

Слабое совпадение

Можно показать характеристики, типовые взаимодействия, набор изучаемых атак и способности; позже на этом построить дуэли питомцев или пошаговые бои.

movetypestatmove-learn-method

Как энциклопедический экран — просто. Как боевая система — крупный отдельный продукт, который меняет фокус с фонового питомца на RPG. Не рекомендую брать без явного желания добавить бои.

Служебная / Игровая эрудиция

Машины, валюты и старые игровые справочники

Низкий приоритет

TM/HM и соответствия атак по версиям, внутриигровые валюты, методы изучения атак, гендерные категории, характеристики и Pal Park-встречи можно вывести в подробную энциклопедию или использовать как исходники для тематических событий.

machinecurrencymove-learn-methodcharacteristicgenderpal-park-area

Данные существуют, но напрямую не улучшают питомца. Имеют смысл как дополнительная Pokédex-вкладка или если проект сознательно расширится в сторону игры по канонам.

Предлагаемая последовательность

Три пути развития

ПУТЬ A · МИНИМАЛЬНЫЙ

Покедекс-карточка

Локализованное имя (если доступно), категория, цвет, среда обитания, короткая запись, оригинальная ветка эволюции. Всё справочное, почти без влияния на баланс.

Подходит, если хочется сделать коллекцию более живой без новых циклов активности.

ПУТЬ B · РЕКОМЕНДУЮ

Индивидуальный питомец

Nature + вкусы ягод + реакции + небольшие косметические/заботные бонусы. Питомец запоминается не только именем и спрайтом, а привычками.

Самый прямой мост между API и текущими Feed, Treats, Care Points и Nature.

ПУТЬ C · БОЛЬШЕ ИГРЫ

Экспедиции и Покедекс

Регионы и места задают темы; активность продвигает вылазки; встречи дают записи и региональный прогресс.

Хорошо, если хочется превратить фоновую активность в приключение и расширить коллекционный слой.

ОТДЕЛЬНОЕ РЕШЕНИЕ

Сражения и сложная эволюция

Атаки, типы, статы и условия эволюции позволяют реализовать оригинальные игровые правила, но это уже крупный поворот продукта, а не «подтянуть ещё данные».

Сначала стоит отдельно подтвердить, что проект хочет стать RPG.

Ограничения и оговорки

Технические

  • API read-only, без входа. Ответы могут ссылаться на другие ресурсы; для одного экрана иногда потребуется несколько запросов.
  • Документация просит локально кэшировать ресурсы. Проект уже имеет кэш спрайтов и каталог — новые данные стоит класть туда же по текущему офлайн-принципу.
  • Списки разбиваются на страницы, обычно по 20 элементов. Полный crawl требует прохода по страницам и аккуратной обработки ошибок/неполных данных.
  • Условные поля бывают null, локализация присутствует не для каждого ресурса/версии. Нужны fallback и скрытие отсутствующих сведений.

Продуктовые

  • PokéAPI — справочник игровых данных, не генератор игровых механик. Значения лечения/атаки/цен не следует напрямую переносить в Care Points и монеты.
  • Локации и условия встреч относятся к конкретным версиям игр; нужен выбор канона или простая нормализация.
  • Полные ветвящиеся эволюции сложнее текущего пути «самая длинная линия». Текущий каталог уже теряет альтернативные ветви для логики стадий.
  • Текущий каталог ограничен Gen I–V. Доступность данных новых поколений в API не означает автоматического расширения проекта: нужны спрайты, баланс редкости, яйца и правила появления.
Рекомендация: сначала профиль Покедекса и интеграция ягод/вкусов с Nature. Это использует уже существующую структуру проекта, добавляет новые решения игроку и сохраняет приложение питомцем, а не превращает его в симулятор боёв.
